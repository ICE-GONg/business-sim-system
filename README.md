# 阿思丹商赛 Streamlit 模拟系统

这是基于原 `business_sim_system`、规则文档和 CPI 模拟器重构的单端口 Streamlit 应用。系统同时提供玩家端与管理员端，并使用 SQLite 保存比赛状态。

## 已实现

- 玩家/管理员登录
- 玩家主场选择、公司命名和全员就绪门槛
- 管理员可代选主场、修改公司名、确认赛前就绪、重置密码
- 管理员队伍管理、玩家/城市删除、玩家决策查看/代改、回合计时与结算
- 第一轮开始后 KDS 自动锁定，管理员明确解锁后方可修改
- 玩家生产、人力、工资、贷款、MA、QI、MI、Agent、价格、报告和专利决策
- 工资均值按主场独立计算，并限制每轮工资涨跌幅；低于本主场均值会按比例自动离职并产生两个月工资补偿
- 第一轮按主场贷款上限计算，第二轮起按净资产、贷款阈值和全局最高贷款动态计算；利息累计进负债
- 504 小时产能、工资相对平均倍率（上限 1.1）、第三轮员工经验倍率
- 材料专利倍率 `0.7ⁿ`、增量仓储、培训费、运输费、利息和税
- 多城市销售、CPI 理论份额、严格按未使用 CPI 进行库存二次分配，0 CPI 不会获得销量
- 按 Net Assets（总资产减负债，包含期末库存价值）排名、官方式分区报表、CPI 市场报告、多队伍财富曲线
- 官方风格的玩家端顶部回合栏、五项导航和折叠式决策表单
- 玩家可下载清晰、完整的官方版式 PDF 回合报表；未购买市场报告时不会显示市场均价
- 市场报表只列出当轮在该城市至少有 1 个 Agent 的玩家
- 可设定比赛总轮数，并可随时中断、清空比赛数据后从第一轮重开
- 管理员可撤销最近一轮结算；现金、负债、库存、专利、员工和 Agent 恢复到结算前，并重新开放该轮
- 管理员可在开赛前选择 -1 测试轮；测试报表保留，正式第一轮开始前恢复完整赛前状态
- SQLite 下载备份、恢复和整场重置

## CPI 算法

结算引擎逐项移植了提供的 `admin.js` 最终算法，并在每个城市独立运行：

1. QI 大量门槛为 `城市最高价 ÷ 50`，最低门槛为 `大量门槛 ÷ 5 ÷ 100`；超过大量门槛后进入第二层，QI 完整池合计 20 CPI。
2. MA 大量门槛由管理员 KDS 设置，最低门槛使用同样公式。
3. MI 大量门槛为 `QI 大量门槛 × 城市市场容量 × 20% ÷ Agent 效益 ÷ 1.5 ÷ 2`，其中 `Agent 效益 = 1 + Agent 数 × 10%`。
4. 每项指数执行赠品、第一层 5 CPI、第二层 10 CPI、福利 1（1.5）和福利 2（3.5）。
5. 投资先乘 `本城市玩家成交加权均价 ÷ 玩家售价`，其中成交加权均价 = `Σ(玩家售价 × 玩家实际售出量) ÷ 玩家总售出量`；价格 CPI 则把低于本城市市场均价的价差按八次方分配 40 CPI。
6. CPI 百分比乘城市市场容量得到理论可售量。若玩家库存不足，其未使用的 CPI 数量按原 CPI 权重分给同城 CPI 大于 0 且仍有库存的玩家；该部分不增加报表 CPI，所以市场份额可以高于 CPI。0 CPI 玩家不会在二次分配中出货。

MA、QI、MI 三个指数池各自严格封顶 20 CPI，价格池严格封顶 40 CPI。投资为 0 时不会获得 `0.01` 赠送 CPI；赠送值只适用于大于 0、但未达到最低门槛的投资。

CPI 在页面和 PDF 中统一显示两位小数，例如 `2.3877%` 显示为 `2.39%`。

## 现金、贷款与投资顺序

- 现金余额不会低于 0；生产量会在产能与可支付材料/仓储成本之间取较低值。
- 销售前的可调投资依次扣除 `MI → QI → MA`，资金不足时当前项只投入剩余现金，后续项归零。
- 销售收入到账后再扣专利投入与市场报告费用，之后计算税前利润和所得税。
- 贷款利息不直接扣现金，而是增加期末负债。
- 本轮获得的专利从下一轮开始按 `patent_factor` 降低材料成本。

## 市场均价

每个城市在结算后生成独立市场均价，并显示在市场报表中：

```text
[Σ(玩家价格 × 对应玩家实际售货量) + 基准均价 × (市场大小 − 玩家总售货量)] ÷ 市场大小
```

第一轮使用该城市 KDS 的初始均价作为基准；之后使用最近一轮已结算的市场均价。未被玩家满足的市场需求仍按基准均价计入，因此少量极端报价不会不合理地拉动整个市场。

注意：上述“市场均价”仅用于市场报表和价格 CPI；QI、MA、MI 中的价格系数使用不含未满足需求的“玩家成交加权均价”。

这是一套透明、可调的模拟算法，不代表官方未公开的后台函数。

## 本地运行

```bash
cd business_sim_streamlit
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
streamlit run app.py
```

打开 `http://localhost:8501`。

初始玩家账号：

- 玩家：`C01`、`C02`、`C03`、`C04`
- 玩家初始密码：`1234`

管理员账号没有默认值。无论本地运行还是云端部署，都必须通过环境变量或 Streamlit Secrets 设置 `SIM_ADMIN_USER` 和 `SIM_ADMIN_PASSWORD`；缺少任一项时管理员登录会被禁用。

## 部署到 Streamlit Community Cloud

1. 把本目录提交到 GitHub 仓库。
2. 在 Streamlit Community Cloud 新建应用，入口文件选择 `app.py`。
3. 在应用 Settings → Secrets 填入：

```toml
SIM_ADMIN_USER = "admin"
SIM_ADMIN_PASSWORD = "你的强密码"
```

4. 部署后先用管理员账号检查 KDS，再让玩家登录。

Streamlit Community Cloud 的本地磁盘不保证跨重启持久保存。每轮结算后请在“备份与重置”页面下载 `.db` 备份；若应用重启，可上传备份恢复。正式长期赛事建议把 SQLite 换成持久化 PostgreSQL。

## 超级 Bot 远程计算（可选）

在 Streamlit Secrets 设置 `SUPER_BOT_REMOTE_URL`（HTTPS 地址）和
`SUPER_BOT_REMOTE_TOKEN`，计算服务器设置相同的令牌。未设置 URL 时仍在
Streamlit 内计算。不要把真实令牌或比赛数据库上传到 GitHub。

- 腾讯云函数：代码包根目录包含 `scf_worker.py` 和完整的 `sim/`，执行方法为
  `scf_worker.main_handler`。先更新计算服务器，再更新 Streamlit。
- 本地 Mac：运行 `local_worker_server.py`，默认只监听 `127.0.0.1:8765`，
  再通过 HTTPS 隧道连接。Mac 必须保持运行、联网且不休眠。
  临时隧道重启可能更换地址，需要同步更新 Streamlit Secrets；正式长期使用应配置固定地址。

远程协议逐个计算并保存超级 Bot，最后执行原有的联合复算。中断后点击“继续分析”
即可处理剩余任务；已经保存的决策不清空。若分析期间比赛数据被修改，会拒绝合并过期结果。
只传输压缩后的计算数据，不传密码哈希或历史数据库备份，也不会用远程数据库覆盖本地整库。

计算优化复用候选之间不变的对手数据，不减少候选、搜索步骤或 CPI 分配内容。
固定比赛备份中 15 个超级 Bot 的本地 M5 测试为 167.59 秒降至 47.88 秒，
所有决策字段（除提交时间）完全相同；实际耗时取决于场上人数和机器。

## 比赛流程

1. 玩家选择主场并提交公司名称。
2. 全部队伍就绪后，管理员选择直接开始第一轮，或先开始 -1 测试轮。
3. 玩家提交决策；提交后立即锁定，玩家可查看但不能再修改，管理员仍可代为修正。
4. 全部队伍提交后，管理员结算。
5. 玩家查看排名与报表；管理员开启下一轮。
